## 一、今天暴露的问题（按重要度排序）

### 1. 自述把两条线揉成了一句

- 我的原话（节选）："……建图保存导航……比较好奇 salm 怎么实现的建图，我利用 ai 帮我写了个最小 SLAM……"
- 问题：① 一句话里塞了"Gazebo 建图-保存-导航闭环"和"手写 SLAM 对比"两件事，
  听的人抓不住主干；② "AI 帮我写"的说法在复试里容易被怀疑贡献度。
- 改法：分两句讲——先说闭环，再说"为了搞懂原理，我借助工具辅助实现了一个最小
  SLAM，但每个模块都拆开理解了原理，并自己设计了同输入对照实验"。被追问"哪里是
  你做的"，就讲你实际做的判断：为什么用 log-odds、为什么加验收门槛、为什么用同一份
  数据对比、无墙环境发散你是怎么排查的。

### 2. 拼写与术语

- `salm` → **SLAM**；"格栅地图" → **栅格地图**；"误差飘逸" → **误差漂移**。
- 口述含糊可以，写进简历/博客前必须检查。

### 3. 分不清"输入数据"和"输出结果"

- 我的疑问："这里的激光和里程计数据是啥东西，栅格地图的数据吗？"
- 标准答法：**输入**是激光（每帧各方向测距 + 角度范围与分辨率 + 有效量程 +
  时间戳 + 坐标系名）和里程计（累积的位移与朝向估计）；栅格地图是算法用这两样
  算出来的**输出**。类比：激光是"每次摸墙摸到多远"，里程计是"凭感觉走了多远"，
  地图是最后画出来的图。

### 4. LaserScan 字段答不全

- 我答："扫描的车距离墙的位置数据"（核心对，不完整）。
- 补全：每帧包含各角度测距值、角度起点/终点/角分辨率、有效量程上下限、时间戳、
  坐标系名；本项目仿真参数是 181 束、2° 间隔、量程 8 m、约 2 Hz。

### 5. 里程计误差来源答得不全

- 我答：打滑 + 逐步累积（核心对）。
- 补全：误差来源还包括轮径/轮距标定误差、编码器量化误差、地面摩擦变化、陀螺零偏；
  累积的原因是"位姿 = 上一次位姿 + 本次增量"，每步误差都成为下一步基准；
  **航向误差还会放大位置误差**（越走越偏）。反过来，激光/GPS 这类绝对观测每次
  对着固定参考，误差不累积——这正是 SLAM 要用激光纠正里程计的原因。

### 6. 不明白"轨迹误差 / RMSE"是什么

- 我的疑问："我不是很明白这个轨迹误差。"
- 标准答法：每一时刻都有两个位置——车真实在哪、算法以为在哪；两点的直线距离就是
  该时刻误差；把整段的误差平方、取平均、开根号，就是 RMSE。本项目修正后 0.315 m，
  意思是**平均偏差约 31 厘米**；真值来自仿真（真实轨迹是我们自己积分出来的）。
- 类比：走过商场，"你实际站在哪"和"你以为自己在哪"的差距 = 轨迹误差；
  "你画出来的平面图和真实布局像不像" = 地图重合度（IoU）。

### 7. 数字说不出来源

- 我的疑问：真值墙厚 0.3、搜索窗口大小、窗口最优值、0.39/0.75——都没有依据感。
- 解法：每个数字归到四类之一——**① 我设定的**（仿真参数）/ **② 我选的**（有理由的
  参数）/ **③ 我算的**（有定义的指标）/ **④ 我跑出来的**（实测结果）。
  见 [STUDY_GUIDE 附录 A](../blog/STUDY_GUIDE.md)。
- 必记的口径坑：`0.315 / 0.453 / 0.347` 出自**无墙世界**（真值只含 5 个障碍）；
  `0.39 / 0.75` 出自**带墙世界**（真值含 4 面墙）。**两组不能直接比较**，报数
  前先声明口径。

### 8. "为什么手写版只有 0.39"第一次答成了循环论证

- 我的答法："因为自身地图的数据就有误差……"（"数据有误差"是循环论证，会被追问
  到底是什么误差）。
- 标准答法分两步：
  1. **位姿其实是准的**：轨迹误差只有 0.09–0.21 m——所以不能把锅甩给定位。
  2. 低的原因：① IoU 是逐格比对，真值墙有 0.3 m 厚，位置或厚度差一两格重合度就
     大幅下降；而且同样放宽容差，gmapping 从 0.32 涨到 0.76、手写版只从 0.23 涨到
     0.39，说明手写版地图的几何一致性本身更差；② 手写版没有回环检测和位姿图优化，
     误差只能局部修正、不能全局拉回，而 gmapping 是粒子群 + 每粒子地图 + 重采样。
- 结论句："**位姿可以准，但地图的精细度和全局一致性不如成熟实现。**"
